- The canonical TradeWorld resolver preserves market, league-specific IDP, liquidity and trend enrichment through both memo entry points.
- V2 market observations preserve actual provider/cache timestamps, stable player identities and source-board settings. Cache expiry cannot override the requested maximum data age. Invalid, stale, future-dated, identity-mismatched, value-mismatched and incomplete-cohort observations cannot support a current V2 price. Observed market dispersion remains separate from an uncalibrated confidence interval.
- Versioned market cohort keys and exact league fingerprints distinguish custom scoring, roster topology, reserve/taxi depth and available format rules. Authenticated canonical and console contexts supply exact numeric NFL rules and specific IDP/flex eligibility to shadow snapshots. Unknown stats, unsupported scoring models/sports, conflicting settings and unknown slots refuse rather than silently approximating. Canonical team capacity now comes from the recorded league size instead of the number of successfully imported teams.
- Market-history ingest writes team count, PPR and the actual observation time independently of its daily deduplication stamp. It reports actual inserted counts, rejects ambiguous identities and invalid prices, and preserves other captures after a write failure. Legacy rows keep unknown metadata. The four existing 12-team PPR board captures remain the ingest scope; demand-based cache profiles are not yet a complete persisted historical cohort series.
- The existing trade grader, waiver scorer and waiver suggestion adapter now live under Decision OS. Their previous module paths are compatibility exports, preserving callers while reducing the engine-boundary backlog from 30 to 27 declarations.
- The shared trade grader refuses a complete grade when any asset is explicitly unpriced or is an unsupported future consideration. Legacy historical snapshots without a valuation-basis field retain their previous interpretation.
- Waiver scoring admits kicker, defense and IDP candidates only with matching starting-position evidence. The waiver AI adapter passes roster topology to that check. Non-finite candidate values are rejected. Existing waiver ranking weights and value floors remain unchanged.
- `lib/decision-os/value-v2` separates market estimates, league transformations and user utility. Estimates preserve source, timestamp, sample size and optional uncertainty bounds. Unknown is distinct from an evidenced zero.
- Exact component scoring supports position-specific bonuses, first downs, defensive components and distance-kick event counts when supplied. Required missing components cause refusal. Fractional flex demand is a transparent structural model; it is not empirically calibrated demand.
- User utility reports separate 1/3/5-year results and refuses missing terms. It requires caller-supplied evidence and common value units; it does not invent conversion factors between fantasy points, probabilities and market values.
- Move calculations support multi-team flows, per-user utility, explicit costs, and incomplete-market refusal. Waiver pair utility subtracts drop value and resource opportunity cost.
- Optimal-lineup matching handles overlapping flex eligibility and multi-position players. Marginal roster calculations check roster capacity, duplicates, ownership and explicit transaction locks. This is an analysis primitive, not an authority to execute a roster move or bypass league rules.
- Paired scenario outcomes produce playoff/survival probability deltas without conflating probability with points or value units.
- The strategy state machine requires three consecutive weekly observations and explicit confirmation. Regrade scheduling defines stable keys for 30-day, end-of-season, 1-year, 3-year and 5-year outcomes, including leap-year handling. Model promotion checks require out-of-time validation, sample floors, improvement, passing invariants and a distinct rollback version.
- Strategy state is durable and scoped to the session owner, league and season. Observations preserve the active strategy while accumulating a proposal; explicit confirmation requires its current revision. State changes and audit events commit atomically, duplicate/stale weeks cannot clear newer proposals, and a competing update returns a conflict. `/api/decision-os/strategy` provides an authenticated owner read, trusted evidence refresh and same-origin confirmation endpoint. It rejects client-supplied evidence and identity fields. Evidence IDs remain internal, and an owner with no state receives `available: false` rather than fabricated history.
- Chimmy includes a league strategy card with explicit confirmation, refresh/retry, stale-proposal handling and cancellation on league changes. Its server producer reuses the existing results classifier with complete closed-week `TeamPerformance` records, recorded team capacity and exactly one claimed owner team. It requires a matching regular NFL season/week, synchronization within 48 hours and an observation loaded within one minute. Unsupported, stale, incomplete or ambiguous evidence does not create proposals. No calibrated probability or dynasty competitive window is claimed.
- Each visit observes only the latest completed week. Three separately observed consecutive weeks are required; the earliest eligible proposal is after completed week five because the classifier first accepts week three. Corrected historical evidence or changed team identity restarts the sequence on the next new week; a same-week correction blocks confirmation immediately. Historical weeks are not replayed to manufacture persistence. The confirmed preference reaches both the standard Chimmy prompt and optional tool loop; pending proposals remain explicitly unconfirmed. Refresh is user-driven through the card, not a scheduled worker.

## Runtime integration and rollout
