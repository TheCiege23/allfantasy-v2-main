## What each URL does

| URL | Current role | Main gap |
| --- | --- | --- |
| `/core/trades` | Trade command center with league strip, value moves, and league search | Previously no way to grade an outside trade without choosing a league. A generic analyzer has now been added locally. |
| `/core/trades?league=<id>` | Two-sided league builder, inbox/history, partner context, grade and advice | Powerful but dense; asset legend can advertise specialty classes the picker cannot add. |
| `/core/trades?league` | Empty query value | It does not identify a league. Treat this as the no-league hub and present a clear league choice. Verify the redirect/state in signed-in production. |

## Visual design by device

| Device | Recommendation |
| --- | --- |
| Desktop | Use a three-zone hierarchy: compact trade inbox/league context, two equal asset columns, then a sticky or adjacent verdict summary. Keep the grade, value difference, and next action visible without scrolling through the long advice stack. The saved screenshot shows small secondary copy and repeated market/format strings; shorten these into a single basis chip with a detail disclosure. |
| iOS and Android | Keep the existing step flow, with a 44px or larger primary action and asset controls. Add a visible progress label (“1 of 3”), preserve a draft between steps, and place the grade immediately after Review. Support photo library/camera/file selection through the image input. Account for safe areas and the software keyboard in the sticky action area. |
| Tablet | Add an explicit 768–1024px layout. The CSS currently switches most trade layouts at 720px, so portrait tablet widths can inherit dense desktop columns. Use one builder column plus a compact sticky summary in portrait, two columns in landscape, and avoid horizontal roster scrolling. |
| All | Increase secondary text size, make muted text pass contrast checks, use words/icons alongside red-green value states, and expose loading, missing-price, stale data, and extraction-error states distinctly. |

## Generic analyzer contract

1. Pick a sport. Enter one player or `2027 round 1` per line under the team sending it, or import a PNG/JPEG/WebP screenshot under 5 MB.
2. Screenshot extraction returns only candidate assets for each side. The user reviews and edits both sides before Analyze. The image is sent to the configured vision provider for extraction and is not persisted by this tool.
3. The existing trade-value route receives `leagueId: null`, `teamContext: neutral`, and `strategy: neutral`. It returns the shared two-sided grade, value totals, and data gaps.
4. Display both sides' grades and market totals. Clearly state that league scoring, roster fit, ownership, eligibility, and acceptance are outside this result. Withhold a letter when the pricing engine cannot grade the deal.

## P0/P1 implementation update

- `/core/trades` and an empty `?league` value now render the trade hub directly. It retains the existing trade-window board, and the offers strip reports pending, unread, or failed provider reads without treating failed reads as zero offers. League tiles also identify a last sync older than 24 hours or an unavailable sync time.
- The league builder's asset legend now shows only asset classes its picker supports. The source-platform action appears again at the verdict. Proposal controls follow the verdict; schedule notes and deeper analysis are disclosures.
- Both grade views identify their value basis. The league verdict exposes per-asset prices and an evaluation time when returned. The generic grade states that it is a market comparison and labels unpriced assets.
- Screenshot extraction requires an explicit confirmation of names and trade sides before analysis. The generic input now has player search with position/team disambiguation, pick year/round/tier entry, and optional overall pick mapped through a stated 12-team reference.
- The CSS adds a portrait-tablet range (721–1024px) that stacks the builder and summary, while keeping the phone step flow below 720px.

The generic analyzer is intentionally market-based; exact pick ownership, league rules, and transaction acceptance remain league-only concerns.

## P2 implementation update

- The league verdict now places partner incentives, an acceptance caveat, and the best regraded counter package near the grade. Selecting the counter package loads it into the builder for another review.
- The existing account-saved league evaluation receipt remains the durable record. Its share image now shows sport, valuation basis, evaluation time, and uncertainty.
- The generic analyzer originally saved comparisons on the current device, scoped to the signed-in account ID where available. Each saved comparison can be reviewed, removed, or downloaded as a PNG card. Old comparisons explicitly require reanalysis before action.

## Follow-on implementation: trade triage and account history

- Cross-league tiles now show a deadline state, latest known offer, and a clear next action. A failed provider scan never reports zero offers; known native offers remain visible as a partial count. Provider rows appearing in both panel lists are counted once.
- Generic comparisons now persist to a signed-in account for cross-device access. Existing device saves are imported once using a stable source ID. The browser retains them if import fails. A user may keep up to 30 account comparisons. The account export includes them, and account deletion removes them.

Before claiming live production verification, check the deployed commit, sign in, test manual and screenshot input with the configured vision provider, and inspect 390px phone and portrait tablet widths. The unauthenticated screenshot endpoint is blocked to protect the vision budget.
