# Tournament scoring adapter: remaining feed gates

Status: internal locked-setup ingestion boundary, not a running provider worker or certified live feed.

## Implemented

- Exact frozen-weight scoring from complete canonical stats. Decimal products are accumulated exactly and rounded once to four places, halves away from zero. Every nonzero weighted stat needs an explicit finite value; no absent/null/string value becomes zero.
- Measured Rolling Insights NBA box-field mapping for supported counting stats and per-game double/triple-double indicators. The 40+ and 50+ scoring bonuses are derived independently from measured per-game points, so a 50-point game earns both when both frozen weights are active. Provider fantasy-point totals are ignored. Fixture: contracts/rolling-insights/fixtures/live.NBA.json.
- DB-backed verified player/game registry checks, one unambiguous current mapping per drafted canonical player and game. An internal immutable provider-ID bridge now covers prepared drafts whose stored ID exactly equals a verified providerPlayerId for every drafted player. It pins the full drafted-to-canonical crosswalk and receipt digest; scoring review rechecks its current registry rows. No name matching or assumptions that equal-looking IDs across different providers belong to the same player. Provider/sport scope and identity expiry are checked.
- Ingest derives the frozen contract in its transaction, compares actual-start attestations to immutable game snapshots, and saves normalized scores plus raw stat evidence and identity provenance atomically. Source and identity mapping drift fail closed. Current registry identities are rechecked before owner review/finalization and standings reads.
- A full coverage batch must reconcile every captured period game and explicitly supply each captured player line. Consecutive raw full-period snapshots now carry order-independent digests and audited correction counts. Prior games/player rows cannot vanish silently; changed facts or finality require newer provider revisions, and complete coverage cannot regress. Identical source/score revisions are compacted; conflicting raw stats sharing a provider/player/game revision are refused even when resulting fantasy points match.

## Not yet certified or connected

1. **NBA full default coverage:** the committed RI box lacks technical/flagrant foul counts, but current frozen defaults enable those penalties. The 40+/50+ bonuses are now deterministically derived from the same game's measured points and use independent indicators, including both at 50+. The raw RI format still fails closed on the full default NBA contract. A captured final-game NBA play-by-play fixture now verifies that the technical action exists, but its only technical is a delay-of-game event with no player ID; no flagrant example appears. It does not prove player attribution, complete event coverage, or correction behavior. The pure inspection helper reports unattributed events and cannot unlock scoring. A full-snapshot comparer now detects changed, removed, reversed and backfilled plays by sparse sequence ID, pins digests, and marks those cases review-required; appended plays stay provisional. This detects changes only when complete current snapshots are supplied, not whether the provider delivered every correction. Do not silently set missing penalties to zero, remove enabled weights, or change a published rules snapshot. Supported-subset fixture tests are a separate explicit test contract, not a product rules change.
2. **NFL game-level facts:** the existing NFL source path is weekly and does not prove individual game attribution or actual kickoff. NFL currently accepts only a trusted complete canonical game-stat envelope. That includes validated special-teams/defense and derived scoring indicators; this module does not invent those from incomplete weekly aggregates. A real provider-to-canonical NFL game adapter is pending.
3. **Draft/provider crosswalk:** the checked draft catalog now preserves per-player source evidence from the selected stored SportsPlayer row: an explicit NFL sleeper_id or NBA rolling_insights externalId. Every other path is marked unknown, including mixed-source external_source_id values without source proof. The immutable provider-ID bridge requires this evidence for every prepared pick, checks the current source row and one verified registry identity per provider ID, and rechecks both during score review. Direct verified canonical mappings remain supported. Unknown/mixed namespaces, stale source rows and missing bench identities block scoring; no name/position/team or coincident cross-provider numeric match is used. Existing catalog snapshots without this provenance need an audited migration before they can use the bridge.
4. **Actual-start proof and postponements:** an owner-triggered check saves immutable, digest-bound Rolling Insights live-status observations for a published game. A nearby `scheduled` → `inprogress` pair can bound when play began; later postponement/cancellation/status regression or a changed scheduled time invalidates that window. The impact preview resolves verified provider-to-canonical game identity and counts affected lineup, score and finalization receipts. The locked-setup score ledger now rechecks saved observations at ingestion, review, finalization and standings reads; contradictory statuses, late lineup locks and claimed starts outside the bound block the week for correction review. A pure ordering check shows that overlapping observation windows cannot determine NBA counted-start order. This evidence does **not** prove exact tipoff or certify every league's lineup lock, and the existing internal `startVerified` scoring assertion is not replaced by the sampler. RI `game_time` is scheduled time, not an independently certified actual start. A worker that samples every game and implements audited correction application and full-period refresh remains necessary before launch.
5. **Coverage/corrections:** the ledger compares saved full-period snapshots and preserves correction revisions, but observedAt and coverage are still trusted worker attestations. No worker, provider polling, correction webhook or raw-response selector was enabled. The comparer cannot prove the provider supplied every correction, and schedule/lineup rebinding after postponement remains blocked. Read contracts/rolling-insights/GAPS.md N-01; do not assume undocumented webhook correction delivery. An empty cached fantasyPoints default is never evidence of scored zero.

It detects missing/duplicate/misclassified game rows and schedule drift, but does not inspect complete drafted-player coverage or ingest scores. Its final-game count is not a scoring readiness signal.
   The check now also audits the measured NBA player-box shape and supported frozen weighted fields, reports malformed/duplicate player rows and unavailable scoring stats, and returns only safe counts. 6. **Staging:** validate identities, source contracts, payload retention, query performance, transaction contention and a complete multi-league season on real Postgres before activation. Existing runtime/lineup/cap/IR/trade and mobile gates remain.
