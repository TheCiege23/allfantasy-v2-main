# Injury + Availability Contracts (Phase 5H-f)

Two **separate** governed contracts. Injury ≠ availability. Code: `lib/sports-data-gateway/persistence/factualDomains.ts`; tables `sports_data.canonical_injury`, `sports_data.canonical_availability` (non-prod). Status: **contract designed · schema created · migration run (non-prod)**. Injury = **provider-verified** (API-Sports live). Availability = **fixture-only** (no gateway-certified source; production availability is a merged token — see below).

## Canonical Injury (`CanonicalInjury`)
`canonicalPlayerId, sport, source, sourcePlayerId, canonicalTeamId, sourceTeamId, injuryType, bodyArea, status, practiceStatus, gameDesignation, description, reportedAt, effectiveAt, retrievedAt, estimatedReturnAt, resolvedAt, freshnessStatus, coverageStatus, identityResolutionState, sourceVersion, correctionOfId, supersedesId, provenance, unsupportedReason, contentHash, version, isActive, createdAt`.
Rules (enforced): append-only/effective-dated; corrections never overwrite prior facts; **unknown status stays unknown, no inferred injury** (never derived from inactivity/missing stats); identity state explicit; sport-isolated; provider terminology mapped but the raw string preserved in `provenance`; stale marked stale; resolved injuries retained as history. Provider verified: API-Sports (`fetchAPISportsInjuries` via team fanout) — real NFL data. Legacy authority (`SportsInjury`, `InjuryReportRecord`) remains default-on and unchanged.

## Canonical Availability (`CanonicalAvailability`)
`canonicalPlayerId, sport, source, sourcePlayerId, canonicalTeamId, availabilityType, availabilityStatus, rosterStatus, practiceStatus, gameDesignation, leagueEligibilityStatus, effectiveAt, retrievedAt, expiresAt, freshnessStatus, coverageStatus, derivationType (observed|derived), derivationVersion, inputReferences[], correctionOfId, supersedesId, provenance, unsupportedReason, contentHash, version, isActive, createdAt`.
Rules: **injury and availability stay separate**; observed vs derived is labeled (`derivationType`); a player with no injury is NOT automatically available; a rostered player is NOT automatically game-eligible; suspended/inactive are NOT injury states; **unknown never becomes available**; derived availability lists `inputReferences` + `derivationVersion`; league lineup legality remains authoritative.

## Why availability is a distinct contract (audit finding)
Production today flattens injury + roster-list + suspension into ONE uppercase token (`SportsPlayer.status` / `PlayerStatusEvent.newStatus` via `AutoCoachEngine.normalizeStatusToken`; `AUTOCOACH_SWAP_STATUSES` mixes `OUT/IR/PUP/NFI` with `SUSPENDED/DISMISSED/TWO_WAY/NOT_ROSTER_ELIGIBLE`). The canonical contract **un-merges** these into injury (facts) vs availability (observed or derived, labeled) vs roster/practice/eligibility fields. Migrating the legacy token onto this contract is REQ-WIRING (deferred; legacy stays authoritative).
