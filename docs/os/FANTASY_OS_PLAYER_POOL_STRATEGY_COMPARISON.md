# Player Pool Selection Strategy Comparison (Phase 27)

**Status: strategies evaluated on real, measured evidence where available; others assessed by direct code/data-availability analysis and disclosed as not implemented/measured.**

| Strategy | Description | Determinism | Provider independence | Real data availability | Runtime/memory cost | Verdict |
|---|---|---|---|---|---|---|
| **F — Alphabetical (baseline, pre-Phase-26/27)** | Order by name, hard limit | Deterministic | Provider-agnostic | N/A (no extra query) | Lowest (one query) | **Measured**: 20.6% resolution — insufficient, this is the defect being fixed |
| **A — ADP-first (chosen, implemented)** | Prioritize players with a real AllFantasy ADP entry, alphabetical tiebreak within tier, graceful fallback to pure alphabetical when no ADP data exists | Deterministic (stable sort, real data) | **Fully provider-agnostic** — AllFantasy's own aggregated ADP, not Sleeper/ESPN/etc. | **Real, already exists** — `AllFantasyAdpSnapshot`, 354 distinct NFL players measured | One additional lightweight query (`distinct` on an indexed-scale table, ~1,431 total rows) | **Measured**: 87.5% resolution, 7/7 real stars resolved. **Chosen.** |
| **B — Rostered-first** | Prioritize players currently on a real fantasy roster | Deterministic if implemented carefully | Provider-agnostic (uses internal `Roster` data) | Would require joining against `Roster`/roster-slot data per league, not a global signal — more invasive, league-scoped rather than sport-scoped | Higher — would need a league-specific join instead of a sport-wide cacheable-shaped query | **Not implemented.** Real fantasy relevance and "currently rostered" are correlated but not identical (a top waiver-wire free agent is fantasy-relevant but not rostered) — ADP is a better general-purpose signal for this shared, multi-consumer resolver. |
| **C — Hybrid ADP + active roster** | Combine A and B | Deterministic if implemented carefully | Provider-agnostic | Real data exists for both halves | Highest of the deterministic options — two additional queries/joins | **Not implemented this phase** — Strategy A alone already achieved the measured 87.5% result; adding roster-join complexity was not justified by the evidence without first seeing whether A alone was insufficient (it was not). |
| **D — Depth-chart priority** | Prioritize by real depth-chart position (starter vs backup) | Deterministic if depth-chart data is reliable | Provider-agnostic in principle, but real depth-chart data quality/coverage was not verified this phase | **Not measured** — data source and its reliability for this purpose were not audited this phase | Unknown | **Not evaluated with real data** — disclosed as a genuine unknown, not dismissed; a real candidate for a future refinement if Strategy A's residual small-limit gap (see below) needs closing. |
| **E — Popularity/usage ranking** | Prioritize by real usage/ownership signals (e.g., roster percentage across the platform) | Deterministic if the underlying signal is stable | Provider-agnostic (internal usage data) | Not verified this phase whether a real, reliable, sport-wide "usage rank" data source already exists | Unknown | **Not evaluated with real data** — same reasoning as D. |

## Why Strategy A was chosen over B/C/D/E without exhaustively implementing and measuring all of them

Per this phase's explicit "smallest safe improvement" and "minimal regression risk" guardrails, Strategy A was implemented first because: (1) real, already-computed data was immediately available (no new data pipeline needed); (2) it directly and precisely targets the exact real defect measured in Phase 26 (real ADP-listed players not resolving); (3) it produced a dramatic, real, measured result (20.6% → 87.5%) on the first real test against `.env.test`. Per this phase's own instruction ("Implement only the strategy that provides the best balance... No consumer code should require modification"), once Strategy A's real result cleared a high bar, further exhaustive implementation of B–E to comparison-shop against an already-strong, low-risk, already-correct result was not justified — those remain real, viable candidates for a future refinement (specifically to address the disclosed residual small-limit gap), not implemented or discarded, simply not needed this phase.

## Residual gap A does not fully close

At limits smaller than the ADP-relevant population size for a sport (354 for NFL), a late-alphabet ADP-relevant player can still be excluded by the within-tier alphabetical tiebreak. A future refinement — sorting *within* the ADP tier by actual ADP rank (already available as `averageOverallPick` on `AllFantasyAdpSnapshot`) instead of alphabetically — would likely close this residual gap without needing Strategy B/C/D/E at all. Not implemented this phase; disclosed as the natural next increment.
