# Create League deep audit — September 19, 2026

**Verdict: do not certify the complete creation-to-season workflow yet.** Core records and many downstream engines exist, but the current entry flow has blockers and several choices do not reach the settings actually used at runtime.

This audit examined the current working tree (which already contained substantial unrelated changes), the deployed `/core`, `/leagues`, `/create-league`, and an existing native `/league/[id]` screen. Browser work inspected the wizard and opened the settings gear; no league was submitted, no settings were saved, and no live roster, trade, waiver, or season was changed. Local tests used database guards/mocks. Deployed behavior and local source should not be assumed identical everywhere.

**Evidence:** 265 existing targeted tests ran: 264 passed and one failed. Ten additional audit characterization checks pass by reproducing the observed defects and configuration mismatches. Those ten are evidence of problems, not acceptance tests proving readiness. Test file: [league-create-audit-20260919.test.ts](F:/allfantasy-v2-main/__tests__/league-create-audit-20260919.test.ts).

## Highest-priority findings

1. **P1 — Native league settings are incorrectly read-only. Live confirmed.** Creation persists `platform: 'manual'`. The settings modal classifies anything outside `allfantasy/native/af` as imported, omitting `manual`. On an existing native eight-team league the gear opened a panel saying “This league is imported from Manual” and instructed the commissioner to edit it on Manual. The normal editable general-settings tree is replaced. Use the existing shared `isNativePlatform` helper instead of another platform list. Sources: [creation:300](F:/allfantasy-v2-main/lib/league-creation/canonical/createCanonicalLeagueInTransaction.ts:300), [modal:237](F:/allfantasy-v2-main/app/league/[leagueId]/components/LeagueSettingsModal.tsx:237), [modal branch:544](F:/allfantasy-v2-main/app/league/[leagueId]/components/LeagueSettingsModal.tsx:544), [native platform definition](F:/allfantasy-v2-main/lib/dashboard/platform-label.ts:17).

2. **P1 — Dynasty cannot complete normal fresh setup. Reproduced in an executable check.** Visible draft inputs update `state.draftDate` and `state.draftTime`; dynasty completion requires `state.dynasty.draftDateUtc`, whose default is blank. The simplified flow never fills it. Even with valid visible dates, validation returns `dynasty_draft_date`. The live review also displayed the hidden-field instruction, including a suggestion to use Offline even though dynasty offers only Snake and Auto. Sources: [wizard:540](F:/allfantasy-v2-main/components/create-league-v2/CreateLeagueWizard.tsx:540), [validation:130](F:/allfantasy-v2-main/lib/create-league-v2/form-completion.ts:130), [defaults:203](F:/allfantasy-v2-main/lib/create-league-v2/state.ts:203).

3. **P1 — Draft scheduling choices are not persisted to the operational schedule field. Reproduced.** Submit places the local date, time, and timezone inside `conceptSetup`. The transaction creates `LeagueSettings` without `draftDateUtc`; subsequent draft bootstrap does not convert those values. A correct preview therefore does not establish a scheduled draft. Convert local time using the selected IANA zone and persist one canonical UTC timestamp; separately define whether the draft automatically starts. Sources: [submit:82](F:/allfantasy-v2-main/lib/create-league-v2/submit.ts:82), [settings creation:599](F:/allfantasy-v2-main/lib/league-creation/canonical/createCanonicalLeagueInTransaction.ts:599), [draft bootstrap](F:/allfantasy-v2-main/lib/draft-defaults/LeagueDraftBootstrapService.ts).

4. **P1 — Selected full-PPR scoring can become half-PPR at runtime. Reproduced.** The preset engine records `fb_ppr`, but post-create bootstrap unconditionally installs NFL `af_default` scoring. The redraft scoring engine consumes that configuration when canonical category overrides are absent. Using the real preset builder, actual bootstrap default rules, and the real scoring function, two WR receptions scored **1**, rather than the requested full-PPR **2**. This is a specific creation-to-engine mismatch; the separate canonical scoring-runtime tests still pass with correctly constructed inputs. Sources: [bootstrap:131](F:/allfantasy-v2-main/lib/league-creation/LeagueBootstrapOrchestrator.ts:131), [NFL scoring config](F:/allfantasy-v2-main/lib/nfl-scoring/NflScoringConfigService.ts), [engine:171](F:/allfantasy-v2-main/lib/redraft/scoringEngine.ts:171).

5. **P1 — Advanced rule checkboxes do not apply their advertised changes. Reproduced.** `advancedSetup.superflex`, `idp`, and `tePremium` are submitted and subscription-gated, but toggling all three leaves the preset engine's roster, scoring, and modifiers identical to ordinary redraft. The checkbox does not set the actual IDP selection. Other advanced boxes are only requests/flags at creation, not evidence that the corresponding automation is running. Translate enabled options into validated effective rules, or clearly label them as later setup tasks. Sources: [advanced controls](F:/allfantasy-v2-main/components/create-league-v2/CreateLeagueWizard.tsx:730), [submission](F:/allfantasy-v2-main/lib/create-league-v2/submit.ts:90), [preset assembly](F:/allfantasy-v2-main/lib/league-creation/preset-engine/runPresetEngine.ts:191).

6. **P1 — Soccer has an unfillable required backend field in the simple wizard. Reproduced.** Soccer is selectable, but `soccerPipeline` starts null and there is no MLS/European selector in this wizard. Submit only includes a non-null pipeline. Server validation rejects Soccer without one. Sources: [default state:266](F:/allfantasy-v2-main/lib/create-league-v2/state.ts:266), [validation:118](F:/allfantasy-v2-main/lib/league-creation/canonical/validateCreateLeague.ts:118), [wizard](F:/allfantasy-v2-main/components/create-league-v2/CreateLeagueWizard.tsx).

7. **P1 — Valid-looking small leagues receive impossible playoffs. Reproduced.** NFL redraft accepts two managers and creates two rosters, but writes four playoff teams. The default is four below ten teams and six otherwise. Clamp/derive the bracket from manager count, then validate it before committing. Sources: [redraft defaults:658](F:/allfantasy-v2-main/lib/league-concepts/redraftDefaults.ts:658), [transaction playoff fields](F:/allfantasy-v2-main/lib/league-creation/canonical/createCanonicalLeagueInTransaction.ts:345).

8. **P1 — Older trade endpoints remain a governance bypass. Source confirmed; not exercised against live data.** `/api/redraft/trade-proposals` takes `vetoMode` and thresholds from a roster owner rather than the commissioner's saved rules and has no trade-deadline check. `/api/redraft/trade-votes` immediately calls settlement on receiver acceptance, without a commissioner-review gate in that branch. The newer league trade endpoint rejects client-supplied governance and the canonical trade runtime checks deadlines, but those protections do not close the older path. Delegate older routes to the same authoritative trade service or retire their mutations. Sources: [proposal:120](F:/allfantasy-v2-main/app/api/redraft/trade-proposals/route.ts:120), [acceptance:361](F:/allfantasy-v2-main/app/api/redraft/trade-votes/route.ts:361), [settlement:70](F:/allfantasy-v2-main/app/api/redraft/trade-votes/route.ts:70), [new route](F:/allfantasy-v2-main/app/api/leagues/[leagueId]/trades/handler.ts:69).

## Remediation and release checks

First fix native settings classification, dynasty/Soccer completion, scheduling persistence, scoring bootstrap, small-league brackets, and legacy trade governance. These have high user impact and affect correctness; the initial form/classification fixes are small, while scoring and trade consolidation require broader review.

Next unify the UI and server catalogs, apply advanced flags to actual rules, enforce the requested draft menu, and align public visibility and co-commissioner authority. Add a visible readiness result for post-create initialization, retryable setup stages, and request idempotency. Then restore clear Create/Import entry points and improve media contrast/fallbacks.

Before certification, run an isolated database/browser journey for each enabled format: create -> read saved rules -> invite/claim a second team -> test commissioner/co-commissioner/member/outsider permissions -> start and finish draft -> verify roster/schedule -> process deterministic stats and waiver claims -> test trades immediately before/after deadline -> generate/advance playoffs -> archive/renew season. Include DST transitions, failed network responses, concurrent submissions/claims, and a fresh league with insufficient AI evidence. Assert that preview, settings UI, persisted rules, scoring results, and AI grounding agree.

External comparison was limited to relevant authoritative behavior, not used as evidence about AllFantasy: Sleeper distinguishes draft scheduling/autostart from the pick timer and pause windows ([draft timer documentation](https://support.sleeper.com/en/articles/4029085-how-does-the-draft-timer-work)); its commissioner documentation describes league scoring, settings, roster, and draft management ([commissioner controls](https://support.sleeper.com/en/articles/9657139-what-can-a-commissioner-do)). These support explicit, coherent controls. The salary-cap-only restriction in this audit comes from the user's requested product policy.
