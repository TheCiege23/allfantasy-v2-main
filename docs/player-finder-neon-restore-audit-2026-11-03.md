The original production data remained intact on branch `br-withered-shadow-adur64u9`. After explicit user approval, a snapshot of that original branch was restored to the same live endpoint at 19:38 UTC. The current production branch is `br-twilight-waterfall-adhk83g2`; its `production` name, default flag, and active endpoint were verified. The temporary live branch `br-blue-bonus-ad12y524` and all three manual snapshots remain preserved; do not delete them during this audit.

The brief temporary branch received writes. Read-only comparison found that current production later updated all 1,286 affected rosters and 88 affected leagues. One league's user confirmation and `lastViewedAt` had been overwritten by a later sync; after separate explicit approval, a conditional one-row update restored exactly those two fields and a SELECT verified them.

The wider table audit found 86 Sleeper import completion events and their outbox rows, 24 trade decision snapshots, 17 NCAAF ESPN games, five advice records, and two draft picks on the temporary branch. Current production subsequently recorded the same 86 league/period import completions, recalculated all 12 unique trade input hashes later, refreshed all 17 game keys later, regenerated the same five advice recommendations, and recreated the same two logical draft picks. League teams, matchups, draft sessions, provider sync state, injuries, news, and the changed user profile were also updated later on current production. Three user-specific home-summary cache keys are absent on current production and can be regenerated on the next visit.

The temporary branch still holds 76 sync-run rows and three analytics events that are absent by ID from current production. These are historical telemetry gaps, preserved in that branch and its snapshot. We did not copy stale provider data or duplicate completion events into production. Keep the preserved branches and snapshots until an owner accepts this audit. Before retiring any schema object, assign an organizational retention owner and validate a separate restore procedure that does **not** finalize onto production; Neon snapshot restore defaults to finalizing a new branch unless `finalize: false` is supplied.
